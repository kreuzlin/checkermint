# 0012: Robot avatars generated locally from a seed

- Status: proposed
- Date: 2026-11-18

## Context

Participants get a robot avatar that they can re-roll until they like it
(brief, section 5.2). Avatars are shown on public profile pages, so they
must not depend on a photo. Privacy rules forbid third-party avatar APIs and
external requests; the artwork must have a license that allows this use.

Options checked (2026-11-18):

| Option | Artwork license | Fit |
|---|---|---|
| DiceBear "Bottts" | Remix of "Bottts" by Pablo Stanley, "free for personal and commercial use" (library code MIT). The style page gives no fuller license text. | Robot style, SVG. JavaScript only: needs Node at runtime or pre-generated files. Licence wording informal. |
| Robohash set1 | Artwork by Zikri Kader, CC-BY 3.0/4.0 (code MIT) | Python package exists, but PNG parts and an attribution requirement on every page that shows avatars. |
| Own generator | Our own, part of this repository | Python, SVG, no dependency, simpler look. |

## Decision

Write a small own generator in Python (`avatars` module):

- The profile stores `avatar_seed` (random string). "Neuen Roboter würfeln"
  sets a new seed.
- The seed feeds `random.Random(seed)`, which picks from a fixed set of
  parts drawn as simple SVG shapes: head shape, eyes, mouth, antenna, body
  colour from a small palette with sufficient contrast. Same seed → same
  robot, always.
- The SVG is rendered by a view (`/avatar/<seed>.svg`), cacheable, with no
  external references (no fonts, no images, no scripts); it is generated by
  our code, not uploaded, so it is not subject to ADR 0009.
- The parts are made of plain geometric shapes written in code. They are
  not derived from Bottts, Robohash or any other artwork.

## Consequences

- No license question, no attribution, no JavaScript runtime, no network.
- The look is simpler than Bottts; parts can be added over time. Changing or
  removing parts changes existing avatars, so new parts are only appended
  and the selection logic is versioned if it ever needs to change.
- If the maintainer prefers the Bottts look, the alternative is to
  pre-generate a fixed set of SVGs with DiceBear and ship them in
  `design/`, after confirming the license text with the DiceBear project.
  That would be a new ADR.

## Open

Status "proposed" until the maintainer confirms. The brief forbids
AI-generated badge and logo artwork; avatars are not covered by that rule,
but the parts would be written by Claude Code. The maintainer decides
whether that is acceptable.
