# 0012: Robot avatars generated locally with Robohash

- Status: accepted
- Date: 2026-11-18

## Context

Participants get a robot avatar that they can re-roll until they like it
(brief, section 5.2). Avatars are shown on public profile pages, so they
must not depend on a photo. Privacy rules forbid third-party avatar APIs and
external requests; the artwork must have a license that allows this use.

Options checked (2026-11-18):

| Option | Artwork license | Fit |
|---|---|---|
| DiceBear "Bottts" | Remix of "Bottts" by Pablo Stanley, "free for personal and commercial use" (library code MIT). No fuller license text on the style page. | SVG, but JavaScript only (Node at runtime or pre-generated files). |
| Robohash set1 | "Classic robots" by Zikri Kader, CC-BY-3.0 / CC-BY-4.0; code MIT (README and `LICENSE.txt` of `e1ven/Robohash`) | Python package `robohash` on PyPI, assembles PNGs locally with Pillow. Attribution required. |
| Own generator | Own | Simpler look; parts would be drawn by Claude Code. |

The maintainer chose Robohash.

## Decision

Use the Python package `robohash` (PyPI, MIT) with the artwork set **set1**
only, generated on our server:

- The profile stores `avatar_seed` (random string, not derived from the
  nickname or any personal data). "Neuen Roboter würfeln" sets a new seed.
- A view renders `Robohash(seed).assemble(roboset="set1", ...)` as PNG in a
  few fixed sizes and caches the result (the seed is in the URL, so the
  response can be cached long-term; a new seed is a new URL).
- Only set1 is used; never `roboset="any"`, which could change existing
  avatars when the package adds sets. No background sets unless decided
  later.
- No network access: the Gravatar feature of Robohash is never used, and
  the robohash.org web service is never called.
- Avatars are generated by our code, not uploaded, so they are not subject
  to ADR 0009.

**Attribution (CC-BY).** Every page layout that can show avatars has a
footer link to a credits section on the imprint page with: work
("Robohash set1, Classic robots"), author (Zikri Kader), license
(CC-BY-4.0, linked) and source (robohash.org / GitHub `e1ven/Robohash`),
plus a note that the images are assembled from those parts. The credits are
covered by a test.

## Consequences

- Recognisable robot look without drawing artwork ourselves; no
  JavaScript runtime, no external requests.
- The `robohash` wheel is about 43 MB because it ships all sets; the image
  grows accordingly. Acceptable; if it matters, only set1 could be vendored
  into `design/` with its license.
- Upgrading the package could in theory change how a seed maps to a robot;
  the version is pinned in `uv.lock`, and upgrades are checked against a
  snapshot test of a few seeds.
- If set1's license or appearance ever becomes a problem, switching
  generators changes every avatar; that would be a new ADR.
